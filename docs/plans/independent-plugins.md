## 当前限制

现有 `packages/app/src/plugins/catalog.ts` 和 `context.tsx` 注册随应用构建的插件定义；`packages/frontend-plugin` 提供命令、插槽、面板、服务上下文、存储与生命周期能力。导入 JSON/JSONC 只对已经注册的插件应用配置，不会安装其中命名的软件包。

新增能力是独立模块的安装、持久化、加载和升级。继续复用现有插件宿主，不另建命令或面板系统。TUI 插件依然需要浏览器适配器，不能通过导入 ZIP 自动获得兼容性。

## 用户流程

1. 开发者在独立插件仓库中使用模板与打包工具，生成插件 ZIP。
2. 用户进入前端插件设置，选择“安装插件模块”；原有“导入配置”入口保留。
3. 在不执行代码的情况下展示包名称、ID、版本、兼容性、来源说明和声明能力。
4. 用户确认后保存插件包，再选择启用；安装和首次启用可以在同一次明确确认中完成。
5. 插件立即提供命令或面板，刷新／重开客户端后恢复启用状态。
6. 用户可禁用、更新、回退或卸载；卸载时决定是否一并删除插件数据。

更新预览需要展示当前版本与目标版本。导入相同 ID、相同版本、相同内容时作为幂等操作；相同版本但不同内容不静默替换，应提示重新发布版本。降级是明确的回退动作，不伪装为普通升级。

## 第一阶段范围

- 本地 ZIP 导入，单入口 JavaScript，配套 CSS 与静态资源。
- 受信任的同页面插件运行，复用现有 SolidJS 和 SDK。
- Web 与桌面共用 IndexedDB 包存储；离线加载已安装模块。
- 清单与兼容检查、安装预览、启用／禁用／卸载、失败清理。
- 崩溃或反复初始化失败后的恢复入口，可跳过第三方插件启动。
- 一个独立开发的示例插件，提供命令、面板、持久化数据和资源加载。

第一阶段接受新版本 ZIP 安装，但启用前必须保留上一可用版本，失败时至少提供手动恢复。自动回退、数据迁移协议与开发重载在第二阶段完善。

## 产品与安全边界

同页面插件具有与宿主页面相近的 JavaScript 权限，可访问页面、网络和本地存储。能力清单用于兼容检查、告知与 SDK 约束，不是沙箱；不得将其描述为安全权限隔离。安装时需明确说明只导入信任的模块。

第一阶段不执行安装脚本，不运行 npm install，不加载 Node.js 主进程插件，也不提供后端生命周期管理。打包工具产物不依赖 CDN、远程模块或运行时分块；这属于格式约束，不能保证受信任 JavaScript 本身不发起网络请求。

后续若引入不受信任插件，需要独立 iframe origin/sandbox 与消息桥，重新设计 UI、服务调用和权限接口；不能把同页面 SDK 换一个开关就宣称实现隔离。

## 成功标准

同一个已构建宿主安装包，导入一个构建宿主时尚不存在的插件后，立即出现新命令和面板；重开客户端后可用；禁用后宿主管理的贡献与订阅被清理；更新失败可以恢复旧模块。全过程不重新构建宿主、不更换安装包、不操作后端。

插件超出已有 API、需要新原生能力或不兼容的共享运行时版本时，仍需升级宿主。浏览器清理站点数据会删除本地安装；导入不会自动跨设备同步。
