# OpenCode Front 2.0.27.3

Port revision 3 for upstream OpenCode v2.0.27, commit [`1f4d07a`](https://github.com/anomalyco/opencode/tree/1f4d07a4a519185955ae8ab2ea3607805509e386). The app uses version `2.0.27+3`.

This release refines project grouping and conversation history, and fixes header controls moving or separating when history is enabled.

## New in this release

- Use compact project avatars, native tab typography, quiet counts, and a small current-project indicator. Project headings retain click/keyboard collapse, saved state, and selection reveal in both tab orientations.
- Move search into an icon in the conversation header. Clicking it or pressing Ctrl/Cmd+F opens a floating search box. Escape, the close button, or clicking outside dismisses it; closing from the search controls restores focus to the icon.
- Remove the permanent search toolbar and its offset of the Review control. History gutters now apply only to message frames, preserving header width and button alignment when toggling history or opening a side panel.
- Show short history ticks in the left margin. Hovering expands the ticks and previews the sent prompt with its response summary; click the card or click/drag the ticks to navigate. Touch dragging and keyboard navigation remain available.
- Keep previews readable in light and dark themes, support reduced motion, and limit the tick count for long conversations. Response previews exclude reasoning and stop at the next user or shell turn.
- Use floating search/history action icons above the composer on narrow screens. The existing transcript control returns to the latest content.

Search highlights, result switching, earlier-history loading, collapsible project groups, native GUI extensions, and frontend plugin controls remain available.

## Build and compatibility

The release workflow builds macOS Apple Silicon (arm64) and Windows x64 archives. It does not produce an Intel Mac build. The example plugins are published as a separate source ZIP and are not included in the desktop application.

The macOS app is ad hoc signed and not notarized. After verifying the download, extract the archive, move `OpenCode-Front.app` to Applications, and clear quarantine before opening:

```sh
xattr -dr com.apple.quarantine "/Applications/OpenCode-Front.app"
```

The app connects to a compatible running OpenCode service. The desktop archives do not bundle or manage a backend.

## Validation

The source-boundary audit, all type checks, and 46 tests (231 assertions) passed. The production/PWA build and desktop staging validate version `2.0.27+3` / release tag `2.0.27.3`.

Production-bundled Chromium fixtures checked the actual project-group and navigation adapters, action icons, search popover, and history ticks with test data. Checks cover grouping in both orientations, result switching and dismissal, entering/clicking the preview, mouse/touch dragging, 390/320px layouts, light/dark themes, reduced motion, and bounded ticks with 120 prompts. Header action rectangles remained stable when toggling history, including with the fixture side pane expanded. The full production connection screen and plugin manager also passed smoke checks.

These fixtures do not verify a connected full session screen, live backend pagination, physical devices, or Electron interactions locally. The release workflow verifies the extracted macOS archive's Mach-O signatures and renderer-helper startup before publication.
