# 优化验证与交付计划

返回[计划总览](README.md)。下文保留验证要求；已执行结果与尚未覆盖项目见[实施记录](ux-results.md)，不能把待验收项视为已通过。

## 验证层次

1. 纯逻辑契约：优先扩展既有测试，覆盖错误映射、分组状态优先级和排序稳定性等必要行为。
2. 组件／浏览器：驱动真实组件与状态提供器，夹具仅替代外部服务数据，覆盖焦点、拖拽、折叠、浮层与布局。
3. 完整流程：使用已运行且获准访问的服务验证消息发送、流式输出、权限处理与面板。无环境时明确列为未验证，不能以夹具通过代替。
4. 实际桌面：在 macOS 与 Windows 检查窗口恢复、显示器变化、外部链接和键盘行为。浏览器测试不能替代 Electron 验证。

同一契约保留一个主要测试归属，避免复制大量实现细节断言。新回归测试应在修复前失败、修复后通过。不得为了测试增加生产开关或全局变量。

## 场景矩阵

| 场景 | 必须观察的结果 |
| --- | --- |
| 连接正确／错误凭据、不可达地址、慢响应 | 错误与恢复动作对应；无重复连接、无旧请求覆盖 |
| 多实例、相同项目名与相同会话标题 | 归属明确；状态、导航和排序不串实例 |
| 折叠运行或待操作会话所在分组 | 状态可发现；处理后清除；标题折叠与标记操作不冲突 |
| 打开浮层、过滤、选择、Escape、重新打开 | 焦点流转明确；当前会话可见；折叠偏好不被查询覆盖 |
| 中文输入、键盘导航、触屏与鼠标 | 组合输入不误提交；焦点可见；触屏不依赖 hover 才能操作 |
| 长历史搜索、加载失败、加载中切换会话 | 搜索范围明确；错误隔离；结果与阅读锚点稳定 |
| 查看旧消息时流式输出、返回最新 | 不强制打断阅读；最新内容可快速到达 |
| 横向／纵向布局与侧面板组合 | 控件不分离、不遮挡；长标题截断合理；无页面横向溢出 |
| 插件导入失败、重试、禁用、重新启用 | 配置结果可理解；命令和面板不重复；异常可恢复 |
| 窗口恢复、外接屏移除、缩放变化 | 窗口在可见区域；最大化与正常几何分别恢复 |

至少覆盖浅色／深色、桌面宽窗／窄窗和移动视口。按真实行为差异选择代表性组合，不机械地重复所有排列。包括 200% 缩放、长名称、无会话、单实例和多实例情况。

## 性能方案

使用固定数据种子，记录机器、浏览器、构建提交、视口和后台负载。分别以 20、100、500 个已打开会话测试，实例和项目分布固定；历史消息规模根据基线逐级增加，并明确已加载与服务端总量。测试数据不得包含用户凭据或私人正文。

记录：

- 点击到分组浮层可交互、输入到过滤结果稳定、选择到目标会话可见的耗时。
- 主线程超过 50ms 的长任务及其归因。
- 流式输出期间输入和导航的响应情况。
- 重复打开／关闭、切换实例后监听器、DOM 与内存是否持续增长。

预热后至少重复 10 次，保留原始样本，报告中位数与最慢样本；需要 p95 时扩大样本量。建议以参考设备上常用规模的本地过滤／浮层响应 100ms 内作为待确认目标，不能将其描述为已达成指标。网络加载与本地交互分别计时。

任何回归均先解释来源。优化收益必须使用相同条件的改前／改后比较；现有 tab reducer 基准只能说明 reducer，不代表布局、渲染、搜索或真实会话切换性能。

## 每项交付检查

- 范围与任务对应，未顺带修改无关原生行为。
- 新增适配文件与原生 overlay 已在导入规则中声明；上游来源与许可保持正确。
- 代码修改运行 `bun run check` 和 `bun run build`；根据任务执行适用的浏览器与桌面验证。
- 会话／时间线修改前记录生产基准，完成后比较。浏览器验证包括生产连接页和插件管理页。
- 文档修改校验相对链接、任务编号和 `git diff --check`，无运行时修改时不为文档重跑完整构建。
- 附验证结果、截图或日志位置、未覆盖的平台与风险；将计划状态更新为已完成并记录提交。
- 一项或一组紧密相关任务使用独立 Conventional Commit，便于回滚。
- 提交、推送与发布分开处理；本计划文档不触发 Release 或版本号变更。

## 回退原则

优先回退单个适配提交，不通过关闭原生校验或修改后端绕过问题。新持久化数据需容忍缺失、旧值和损坏值；不要不可逆地重写用户的实例、项目顺序或折叠偏好。涉及窗口恢复时始终保留安全默认尺寸。
