# 独立插件模块实施与验收

返回[功能计划](independent-plugins.md)。所有任务初始为待实施，按下列依赖推进，不预设未经测量的工期。

## 任务拆分

| 编号 | 任务 | 依赖 | 必须交付的证据 |
| --- | --- | --- | --- |
| IP-00 | 运行时加载可行性验证 | 无 | 构建后创建的单入口 Blob ESM 在 Chromium 与 Electron 44.4.5 的 oc 协议夹具加载；共享 Solid context/store/effect/DOM helper、CSP、CSS/图片及清理通过；决策记录。macOS/Windows 实际打包验证保留在 IP-05 平台验收 |
| IP-01 | 清单、打包工具与模板 | IP-00 | 格式说明、类型产物、独立仓库可执行构建命令、产物校验、兼容表 |
| IP-02 | 安装仓库与校验事务 | IP-01 | 非执行预览、ZIP 校验、原子存储、配额失败、多窗口冲突与损坏记录恢复 |
| IP-03 | 动态注册与实例生命周期 | IP-00、IP-02 | 安装定义进入运行时目录；启停与异步竞争测试；命令／面板／样式／资源清理 |
| IP-04 | 管理界面与启动恢复 | IP-02、IP-03 | 安装与配置导入区分；兼容错误、禁用卸载、旧模块手动恢复和跳过第三方启动入口 |
| IP-05 | 独立插件端到端验收 | IP-01～IP-04 | 固定宿主构建摘要不变，安装新插件即时生效、离线重开与卸载结果 |
| IP-06 | 自动回退与迁移契约 | IP-05 | 候选版本失败恢复、版本指针一致、兼容数据迁移及不可回滚事项文档 |
| IP-07 | 开发重载与开发者文档 | IP-05 | 开发模式重新导入生成新实例，错误可诊断、贡献不重复、生产默认关闭开发入口 |

IP-00 是实现门槛；若无法共享运行时或满足现有平台策略，先调整设计，不继续堆叠安装 UI。IP-06/IP-07 可在第一阶段验收后分别推进。

## 第一阶段验收矩阵

| 场景 | 预期 |
| --- | --- |
| 固定宿主构建后创建新插件 ZIP | 导入并启用后出现新命令和面板；宿主产物字节不变 |
| 未确认安装预览 | 不执行入口，不注册贡献，不写入正式安装记录 |
| 无效清单、未知版本或能力 | 执行前拒绝，说明升级宿主或修正包的路径 |
| 路径穿越、重复路径、符号链接、超限文件与解压膨胀 | 拒绝且无部分安装；不写出包外文件 |
| 同 ID 与版本重复导入 | 相同内容幂等，不同内容不静默覆盖；内置 ID 始终保留 |
| Solid context、store、effect、portal 和 JSX | 共享宿主运行时；挂载和卸载正常，无第二套运行时造成的失效 |
| 暗色／浅色、窄窗口、缩放和资源 URL | 样式可读，资源可加载，卸载后无遗留样式影响宿主 |
| 已安装模块离线重开 | 本地加载；自动启用符合用户设置；缺失或损坏记录可恢复 |
| setup 抛错、异步挂起、加载期间禁用／卸载 | 宿主管理的贡献清理；晚到结果不复活已停用实例 |
| 切换会话与实例 | 插件通过 accessor 获取当前服务，旧异步结果不写入新会话 |
| 重复启停 30 次 | 命令、插槽、面板与订阅数量不累加；资源引用释放 |
| 配额不足、事务失败、应用异常退出 | 保留当前可用版本；安装状态可解释；设置恢复入口可进入 |
| 两个窗口同时更新／卸载 | 活动版本指针一致；旧窗口不覆盖新状态 |
| 未安装模块的配置导入 | 提示缺少模块；不下载代码、不冒充成功启用 |
| 卸载保留／删除数据 | 后续重装行为符合选择；不删除其他插件数据 |

第一阶段以受信任模块为对象；静态包约束、CSS 作用域和错误边界不证明恶意代码隔离。同步死循环、任意全局副作用属于同页面模型的限制，需在说明中明确。

## 第二阶段验收

- 新版本初始化失败后，旧版本恢复且只存在一套命令／面板；当前与上一可用版本指针正确。
- 安装候选但未启用，不运行候选代码；卸载中断更新后不会被旧任务重新安装。
- 同版本不同内容、显式降级和跨 API 版本升级有明确反馈。
- 数据迁移失败保留原数据；无法证明可逆时拒绝自动降级并提供明确说明。
- 开发重载可反复替换，不需要重建宿主；重载后旧资源清理。日志标注插件 ID 和版本，不输出凭据、配置秘密或正文。

## 测试与维护要求

扩展现有 `packages/frontend-plugin` 生命周期测试，以及 app 插件管理浏览器测试。归档解析、版本解析、持久化恢复各自测试真实契约；不通过 mock 掉加载器来证明动态安装成功。模块加载端到端测试使用独立 ZIP 产物，不在宿主构建时导入示例代码。

每次代码交付运行 `bun run check`、`bun run build` 和适用的浏览器验证，核对 upstream 导入边界。涉及会话或时间线时按仓库要求记录生产基准。实际 macOS／Windows Electron 必须验证安装、重开、禁用、窗口恢复和 oc 资源加载；浏览器夹具不能代替实机结果。

性能记录包括安装校验耗时、启用耗时、启动额外开销和重复启停后的 DOM／监听器／资源变化。固定环境重复采样，不把单次内存快照当作无泄漏证明。先记录无第三方插件的宿主基线，再测一个小插件与多个插件。

## 完成定义与交付顺序

1. IP-00 形成明确技术决策，再冻结清单和构建契约。
2. 使用独立模板仓库构建至少一个命令＋面板＋图片/CSS＋存储示例，示例不预装到宿主。
3. 证明安装前后的宿主包摘要相同，并记录测试插件构建发生在宿主构建之后。
4. 记录每项验收的通过、失败或未覆盖平台；未覆盖项不能标记已完成。
5. 更新插件 API 文档、迁移说明和恢复指南，注明能力声明不构成安全隔离。
6. 按安装仓库、加载器、管理界面和 SDK 分成可回退的 Conventional Commits。
7. 提交／推送与宿主发布分开处理；实现后首次分发加载器需升级宿主一次，之后兼容插件模块可独立分发。
