## 设计原则

1. 稳定性、简单性、性能依次优先。优先完善已有原生能力，不重复建设命令面板、会话状态或设置搜索。
2. 界面默认保持简洁。详细信息按需通过悬浮、浮层或展开区域展示；不恢复分组数量和 Move earlier/later 菜单，排序继续使用鼠标拖拽。
3. 会话、项目和实例始终明确隔离；切换上下文后不展示上一上下文的结果或错误。
4. 保留原生输入框、Review、文件、终端与权限交互。定制逻辑优先放在适配层；涉及原生修改时先声明 overlay。
5. 本项目仅连接已有服务，不管理后端生命周期。跨历史搜索等需要服务能力的方案先评估接口，不以一次性加载全部消息替代。
6. 新 UI 文案使用 i18n 英文源键，其他语言按仓库翻译流程另行审核。文档语言不等同于产品文案语言。

## 当前基础与证据范围

已具备实例→项目分组、持久化排序与折叠、紧凑横向导航、当前会话定位、浮动消息搜索和历史滑轨。原生命令面板、设置搜索、会话状态和虚拟化时间线继续复用。

分析基于源码与已有浏览器验证。49 项测试及生产构建此前通过，浏览器夹具覆盖 55 个会话，但夹具使用模拟连接与缓存标题。这不能替代真实服务、实际 Electron、长历史流式输出和低性能设备验证。以下“已确认”只描述代码行为；性能影响与部分交互风险仍需测量。

## 实施顺序

| 阶段 | 任务 | 阶段成果 |
| --- | --- | --- |
| 0：建立基线 | UX-00 | 可复现的关键使用流程、性能记录和平台覆盖清单 |
| 1：反馈与恢复 | UX-01、UX-02、UX-03 | 连接失败可处理，折叠会话状态可发现，桌面窗口可恢复 |
| 2：查找效率 | UX-04、UX-05 | 多会话快速定位，历史搜索范围和加载过程明确 |
| 3：规模与完善 | UX-06、UX-07、UX-08 | 大量会话性能验证，插件导入可理解，版本来源清晰 |

UX-00 先建立适用场景基线；后续每项独立交付，不必等待全阶段完成。UX-03、UX-07、UX-08 可独立开发。UX-06 的索引优化应参考 UX-04 的列表数据结构，避免两套索引。发现阻断性问题时优先修复，再推进体验增强。

不承诺未经验证的工期或性能收益。每项开始前补充负责人、范围和测量结果，完成后附提交与验证证据。发布版本单独决定，本计划不授权创建 Release。

## 暂不纳入本轮

- 后端升级、服务启动与重启、内置 SSH 服务管理。
- 没有服务接口支撑的全历史全文检索。
- 自动更新、签名与公证体系重建；先完成版本识别和手动发布说明入口。
- 大范围重写原生 GUI、引入新的全局状态框架或仅为视觉变化增加依赖。
- 在测量之前直接重写列表为虚拟列表。
