# OpenCode Front 2.0.31.0

The first OpenCode Front release based on upstream OpenCode **v2.0.31**, commit [`22728d6`](https://github.com/anomalyco/opencode/tree/22728d67461260d56bb9796b9b8f36e1de47202e). The app uses version `2.0.31+0` and connects to an existing compatible OpenCode service; desktop archives do not bundle or manage a backend.

## New in this release

- Configure installed frontend plugins directly from the plugin manager. Authors can declare text, number, switch and select fields, with descriptions, defaults, required values and numeric bounds. Users can cancel edits, restore defaults in a draft, or save and apply without reimporting a module.
- Saving configuration restarts only the selected plugin and preserves its disabled state. Invalid or missing required options prevent setup and show a repairable configuration status. Hanging setup does not block further editing or disabling. JSON/JSONC imports remain supported, and options not declared in the form are retained.
- Plugin updates and previous-version restoration use the selected version's declaration while preserving user values for repair. Cancelled candidate activations can restore the previous package and its saved data. Configuration errors do not trigger package rollback.
- Updated independent plugin examples declare their configuration in the manifest: panel title/presentation/launcher options and status endpoint/refresh interval. The release includes the independently installable 1.1.0 example packages.
- Upstream GUI changes add optional changed-file summaries and expandable diffs after completed turns, session navigation with Alt/Option+Up/Down and unread-session navigation with Shift, voice delegation presentation, missing-project-folder feedback, and settings error containment.
- Upstream fixes improve side-panel animation, attachment drops, artifact media display, file-tree styling, animated counts and dialog behavior. The Corvu drawer patch prevents a rapid close during opening from leaving the drawer stuck.

Existing plugin panels, history navigation and project grouping remain integrated. Changed-file summaries are disabled by default under **Settings → Preferences → Timeline → Changed files**. See the [upstream sync record](../upstream-v2.0.31.md) for import boundaries and measurements.

## Validation

`bun run check` passed the source-boundary audit, type checks and 90 tests (519 assertions). The production/PWA build passed. Production Chromium keepers covered connection validation, credential correction, timeout/cancel handling, pairing recovery, plugin configuration imports, grouped-session browsing/filtering and paginated history search without page errors. Declarative configuration was also exercised in the production browser build, including editing, cancellation, default restoration, persistence, disabled plugins, hanging setup, updates and previous-version restoration.

The performance fixture measured production adapters with simulated providers, not real transcripts or service latency. Ordinary dependency installation passed; Bun 1.3.14's previously recorded frozen-lockfile issue with the patched Git dependency remains, and CI uses ordinary installation. Real connected-session behavior for the new turn-diff feature, packaged native interaction, Windows hardware, physical mobile devices and long-running resource use remain unverified locally. No running user app or backend was restarted. The release workflow verifies the extracted macOS archive's Mach-O signatures and renderer-helper startup before publication.

## Downloads and compatibility

The release workflow builds macOS Apple Silicon (arm64) and Windows x64 archives, a separate frontend plugin example source ZIP, and two independently installable plugin ZIPs. Examples are not bundled into the desktop app.

The macOS app is ad hoc signed and not notarized. After verifying the download, extract the archive, move `OpenCode-Front.app` to Applications, and clear quarantine before opening:

```sh
xattr -dr com.apple.quarantine "/Applications/OpenCode-Front.app"
```
