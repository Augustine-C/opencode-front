# Upstream maintenance

The source version is pinned in `upstream.json`. Run `bun run upstream:plan --source <checkout> --ref <commit>` before importing, inspect every overlay and collision, update provenance, then run `upstream:record` at that exact commit. Run `bun run check` and `bun run build` before delivery. Preserve unrelated checkouts and lockfiles.

The import policy and inventory classify every file as pristine, a declared overlay or port-owned. GUI built-ins now live in `packages/gui-plugins`; the GUI SDK and RPC re-export are a partial import of `packages/plugin`. Server/core/TUI implementations remain excluded. The selected official desktop main host, lifecycle, SQLite storage, embed implementation and renderer bridge are imported from the same upstream commit. `packages/patchmark` supplies the upstream session markdown parser. Dependency patches must match the exact imported package versions.

The official `runtime/plugin` host owns plugin activation, storage and contributions. The CodeArts definition list is composed in `src/extensions/native.ts` and included through the `runtime/plugin/builtins.ts` overlay. Do not restore `packages/frontend-plugin`, `src/plugins`, custom slot mounts or the browser panel bridge. Keep the existing-service connection overlay, project grouping adapters, build information, and history navigation mounts. See [v2.2.0 migration](upstream-v2.2.0.md).

The Electron shell attaches the official main host to an existing configured HTTP service and exposes the complete official GUI `Bridge` through a bounded native IPC transport. Keep bundle evaluation, activation, schemas, storage and embeds in the upstream modules; adapters must not become a second plugin runtime. The renderer consumes only the bundles main publishes. Do not start or manage a local backend. Preserve plugin-contributed server connections when changing routes. See [native plugin adaptation](native-gui-plugins.md).
