# OpenCode Front 2.0.29.0

The first OpenCode Front release based on upstream OpenCode **v2.0.29**, commit [`042d083`](https://github.com/anomalyco/opencode/tree/042d0832f5f3a73eaa039a58a7d565776f6d4290). The root/Electron version is `2.0.29+0`.

This release combines the upstream GUI update with the completed user experience plan and two review fixes.

## New in this release

- Recover from connection failures with clear status, cancellation of stale checks and a preserved service address after paired credentials are rejected.
- See attention status on collapsed session groups, restore desktop window geometry across display changes, and filter open sessions by title, project and instance.
- Search loaded history and explicitly load earlier pages with a bounded search operation. Search selection remains on the same match as older results are prepended.
- Review plugin configuration imports before applying them, see actionable initialization failures, and retry setup safely.
- See client build provenance, upstream GUI version and connected service version separately.
- Keep group membership indexes and filter labels cached for large session lists.
- Use upstream v2.0.29 frontend changes, including provider account management, pending steer visibility, session cost/token display, image zoom/pan, media caching and improved focus handling.

The full implementation record, measurements, and remaining platform/service acceptance work are in the [UX plan results](../plans/ux-results.md). The app connects to an existing compatible OpenCode service; it does not bundle or manage a backend.

## Downloads and compatibility

The release workflow builds macOS Apple Silicon (arm64) and Windows x64 archives, plus a separate example-plugin source ZIP. Examples are not bundled into the desktop app. The macOS application is ad hoc signed and not notarized. After verifying the download, extract the archive, move `OpenCode-Front.app` to Applications, and clear quarantine before opening:

```sh
xattr -dr com.apple.quarantine "/Applications/OpenCode-Front.app"
```

## Validation

The source-boundary audit, all type checks, and 57 tests (291 assertions) passed. Production/PWA and adapter-fixture builds passed. Five Chromium browser keepers covered the production connection screen and plugin manager, plus the grouping, history search and version adapters. The pairing recovery and paginated first-match regressions were reproduced before their fixes. Desktop staging validates the release tag mapping to `2.0.29+0`.

Browser fixtures use synthetic responses and mock session data. Live service workflows, full virtualized transcript behavior, physical devices and packaged macOS/Windows execution remain unverified locally. The release workflow verifies the extracted macOS archive's Mach-O signatures and renderer-helper startup before publication.
