# OpenCode Front 2.0.28.0

The first OpenCode Front release based on upstream OpenCode **v2.0.28**, commit [`026b106`](https://github.com/anomalyco/opencode/tree/026b106bc5d41b679ffc413264229c340871e4d3). The root/Electron version is `2.0.28+0`.

This release combines the upstream update with instance-first project grouping and saved group ordering.

## Instance and project grouping

- With **Group tabs by project** enabled, each connected OpenCode instance forms one contiguous block. Its projects and their sessions appear inside it. Identical project names or paths on different instances remain separate.
- Collapse either an instance or a project. Selecting a session expands both owning groups; users can still fold the active group themselves. Collapse state persists across reloads and layout changes.
- Drag instance headings to reorder blocks, or project headings to reorder projects within their instance. Projects cannot move across instances.
- Each heading's **…** menu provides **Move earlier** and **Move later**, including on mobile. Focus a heading toggle and use **Alt+Up/Down** or **Alt+Left/Right** to sort with the keyboard. Focus follows the moved heading.
- Save instance and project ordering independently. Temporarily closed groups keep their saved positions; old grouping preferences remain compatible.
- Preserve native project-scoped session dragging, keyboard cycling and numbered shortcuts in both horizontal and vertical layouts.

Floating search, Codex-style message-history ticks and prompt/response previews, the frontend plugin manager, and the native CodeArts Proxy extension remain available.

## Upstream v2.0.28 changes

- Per-project permission auto-accept settings can override the client-wide default.
- Unread activity follows server viewed/idle watermarks, with migration of previous client-local viewed state.
- Submitted prompts appear as the composer clears; Working status stays above undelivered steers. Mobile timelines simplify model/agent details.
- Close Tab ignores collapsed side-panel tabs. Session cost includes subagent sessions.
- Review previews load images and audio; video previews expand into an in-window theatre view while preserving playback.
- Dialog focus restoration handles stacked/replaced dialogs and the composer caret. Provider/model compatibility schemas and generated client/protocol contracts are refreshed.

See [upstream sync details](../upstream-v2.0.28.md) and [grouping design and validation](../instance-project-groups.md).

## Downloads and compatibility

The release workflow builds macOS Apple Silicon (arm64) and Windows x64 archives, plus a separate example-plugin source ZIP. Examples are not bundled into the desktop app. The frontend connects to an existing compatible OpenCode service and does not bundle or manage a backend.

The macOS application is ad hoc signed and not notarized. After verifying the download, extract the archive, move `OpenCode-Front.app` to Applications, and clear quarantine before opening:

```sh
xattr -dr com.apple.quarantine "/Applications/OpenCode-Front.app"
```

## Validation

The source-boundary audit, all type checks, and 49 port tests (241 assertions) passed. The upstream sync also passed 44 upstream model/timeline tests (117 assertions) against the imported sources. Production/PWA build and desktop staging passed.

Chromium checks mounted the actual native tab strip, group adapters and settings persistence with mock connection/project data and draft tabs. Instance/project dragging, cross-instance rejection, native project-scoped tab dragging, menu and keyboard ordering/focus, collapse and selection reveal, reload/legacy settings, horizontal/vertical layouts and 390px mobile controls passed. Floating search/history adapter checks covered 1280/390/320px layouts, mouse/touch navigation and stable header control positions. The production connection screen and plugin manager passed smoke checks with no page errors.

Live backend sessions and physical devices were not tested. The release workflow verifies the extracted macOS archive's Mach-O signatures and renderer-helper startup before publication.
