# 独立插件包与运行时设计

返回[功能计划](independent-plugins.md)。IP-00 已验证运行方式并冻结第一版包契约；示例字段仍需对应的 IP-01～IP-03 实现后才会由宿主支持。

## 包结构与清单

```text
service-dashboard.zip
├── manifest.json
├── main.js
├── style.css
└── assets/
    └── icon.svg
```

```json
{
  "formatVersion": 1,
  "id": "example.service-dashboard",
  "name": "Service Dashboard",
  "version": "1.0.0",
  "apiVersion": 1,
  "runtimeVersion": "solid-v1",
  "entry": "main.js",
  "styles": ["style.css"],
  "capabilities": ["session.read", "commands.register", "panels.register"]
}
```

`formatVersion`、`apiVersion` 与 `runtimeVersion` 分别描述包格式、宿主 API 和共享渲染运行时契约，不直接绑定 OpenCode GUI 每个版本。`solid-v1` 是待验证的运行时契约标识，并非 SolidJS 的 npm 版本兼容承诺。冻结时提供明确的宿主支持表。清单可有描述、作者、源码链接与许可证；自报来源不是已验证身份。

校验要求：

- ID 使用有命名空间的稳定格式；内置 ID 保留，第三方包不能覆盖；插件定义 ID 与清单必须一致。
- 版本使用 SemVer；未知格式、API 主版本、运行时契约及必需能力在执行代码前拒绝，并给出可操作说明。
- 入口与所有资源须为包内规范化相对路径，检查缺失文件、重复文件名、大小写冲突、绝对路径、`..`、反斜杠和符号链接等歧义；ZIP 不解压到用户文件系统。
- 读取过程中限制压缩包大小、解压总量、文件数和单文件大小，不能先完整解压再检查。建议起始限制为 20 MiB 压缩包、50 MiB 解压总量、1,000 个文件，IP-00 后根据示例确定并统一在 UI 告知。
- 为每个内容版本计算摘要用于完整性、幂等与存储寻址。摘要不是作者签名，也不证明可信。
- 预览仅解析静态清单与文件元数据，不能执行入口或调用插件提供的预览函数。

## 独立构建与共享运行时

首选产物为单文件 ESM，默认导出一个接收宿主运行时的工厂，由工厂返回现有 SDK 的插件 Definition。工厂参数和函数名在可行性验证后定稿。

构建工具负责将开发时的 `solid-js`、`solid-js/web`、`solid-js/store` 及 SDK 运行时引用转为宿主注入的共享 facade；其他浏览器依赖打进主文件。禁止产物残留裸模块导入、相对 JS 分块和对宿主 `@/` 内部路径的依赖。不要让插件带入第二份 SolidJS：需要验证 context、owner、effect 清理与 JSX 编译结果共享同一运行时。

工具应生成版本信息、清单与 ZIP，并对产物做结构检查；不能把简单正则检查当作任意恶意代码的安全审计。宿主不在用户机器上编译 TSX、不从包仓库安装依赖。

稳定 SDK 提供宿主已有 `context.ui.command`、`context.ui.panel.register/open`、插槽、存储、连接与会话 accessors。对外导出的类型也需要可独立获取，避免模板依赖 monorepo 私有路径。第一阶段仅提供明确受支持的 UI 原语；不暴露整个上游 UI 内部模块。

## 模块与资源加载

首选通过保存的入口字节创建模块 Blob URL 后 `import()`，再调用工厂注册定义。必须先在实际 Web CSP 与 Electron `oc://renderer` 上验证，不以关闭 sandbox、启用 Node integration、`unsafe-eval` 或禁用浏览器安全机制作为解决方案。若该路径不可用，应记录原因并评审受控资源路由方案，再冻结格式。

JS 模块使用新 URL 区分内容版本，初始化结果进行结构校验。所有对象 URL 都由单个插件实例的资源所有者管理。CSS 与图片需有统一资源解析器：插件通过拟议 `context.assets.url(path)` 访问包内资源，CSS 构建时提取并校验 `url()` 引用，宿主使用 CSS 解析器重定位，禁止递归远程 `@import`。生命周期结束后清理样式、资源 URL 和挂载节点。

第一阶段建议给样式增加插件 ID 根容器作用域，并提供宿主设计 token。样式作用域是避免误污染的约定，不是对同页面代码的隔离。暗色模式、字体、溢出与焦点样式需在示例中验证。

## 存储与配置分离

建议 IndexedDB 保存两类数据：

| 数据 | 内容 |
| --- | --- |
| 模块内容记录 | 内容摘要、原始清单、入口/CSS/资源字节、安装时间 |
| 插件安装记录 | ID、选中版本、上一可用版本、待激活版本、初始化状态 |

模块字节不得写入 localStorage。现有插件配置保留选项与启用意愿，业务数据仍走按插件 ID 隔离的 storage。迁移后本地模块、内置定义与配置合并成统一可用列表；未安装的配置项显示未安装，不偷偷联网下载。

安装先完成全包校验，再通过一个 IndexedDB 事务提交内容和安装记录；配额不足或事务失败不修改当前可用版本。模块存储与原有配置存储不能跨数据库保证原子性，需要以安装记录为权威，启动时协调无效启用项；不能假设两次写入天然构成事务。

多窗口／多标签页需要版本冲突控制与变更广播，避免同时升级或卸载导致版本指针被旧窗口覆盖。Web 和 Electron 使用各自 origin/profile 存储，不承诺互通或自动同步。

## 生命周期与失败恢复

状态应区分包状态与实例状态：已安装不等于已启用；实例包含未加载、加载中、运行中、停用中、失败。每次启用有独立 generation 和 AbortSignal；过期 setup 完成后不能重新注册贡献。

统一复用现有 host 的生命周期，动态注册需要补齐移除／替换定义的契约。定义列表、配置导入匹配和设置界面都必须响应动态变更，不能继续持有启动时的静态 catalog 快照。

禁用顺序：终止该实例的异步工作 → 销毁宿主注册的命令、插槽、面板、事件订阅与 Solid owner → 执行并等待适用的插件 cleanup → 释放样式和资源。卸载还移除定义和包引用；数据是否删除单独确认。宿主可保证其管理的资源清理，但无法强制清理插件私自创建的定时器或全局监听。

启动恢复：先让设置和恢复入口可用，再加载第三方插件；记录激活标记与明确的异常结果。异常退出标记只能提示可能相关，不足以证明某个插件导致崩溃。提供下一次启动跳过第三方插件的恢复方式。同步死循环会阻塞主线程，Promise 超时无法终止它；第一阶段不承诺同页面插件故障的完全隔离。

## 更新、回退与数据迁移

下载／导入和启用分离。新版本完成静态校验后保存在候选记录中；暂停旧实例并清理，尝试加载候选，成功后更新活动指针，失败则清理候选并恢复旧版本。没有旧版本时保持插件禁用并保留诊断。未启用的插件更新不应偷偷运行 setup。

第二阶段实现自动回退之前，第一阶段必须保留旧模块并提供手动恢复。保留策略至少覆盖当前和上一可用版本，删除无引用内容。

模块回退不等于数据回退。第一阶段插件更新须保持存储向后兼容；第二阶段评估版本化数据命名空间和复制后迁移。外部 API 写入、文件操作或账号操作不能由模块加载器自动撤销，不得宣称全局事务回滚。

## 上游边界与开放问题

安装仓库、加载器、资源所有权和管理 UI 放在 port-owned plugin/extension 模块；SDK 只增加明确稳定接口。原生 shell、面板和命令系统维持薄挂载，新增 overlay 需登记导入规则。

IP-00 必须形成决策记录：Blob 模块在目标平台可用性、运行时 facade 的最小导出、Solid 编译器兼容范围、资源重定位方式、存储配额表现、启动恢复入口。未决项解决前，不对外宣称任意 npm 包、任意 UI 组件或不受信任插件兼容。
